## 一、崩溃与资源泄漏

### 1.1 退出后残留后台进程

**现象**：主程序关了，`InkCanvas.IACoreHelper.exe` 还挂在任务管理器里。
反复开关几次会积累多个残留进程。

**根因**：子进程没有父进程退出检测。主进程正常退出、被强杀、崩溃，
子进程都感知不到。

**修复**：给 helper 加父进程看门狗，父进程一消失就自我结束。

**验证**：任务管理器强杀主进程 → 确认 helper 跟着退出，无残留。

### 1.2 跨线程访问 DynamicRenderer

**根因**：原判据靠匹配异常消息里的英文字符串。
Windows 换成非英文语言后，这条判据永远匹配不上，
本该拦住的跨线程访问就放过去了。

**修复**：改成语言无关的判据（比对异常类型与 HRESULT，不看消息文本）。

**影响**：中文、日文等非英文系统上都受益。

### 1.3 墨迹转形状时的内核句柄泄漏

**现象**：长时间批注后，进程句柄数缓慢上涨。

**根因**：走 WinRT 形状识别的路径，每落一笔泄漏一个内核句柄。

**修复**：形状识别默认改走 IACore，不再每笔新建 WinRT 识别器。

## 二、功能异常

### 2.1 与其他版本共存时互相干扰

**现象**：同时装上游原版和本分支，任务栏图标合并、配置互相覆盖。

**根因**：两者用同一个 AppUserModelID 和互斥体名。

**修复**：

- AppUserModelID → `InkCanvasForClass.LTSC`
- 互斥体 → `InkCanvasForClass CE LTSC`

**刻意保留**：`AssemblyName` 仍是 `InkCanvasForClass`。
改了会让「检测原版是否在运行」的判断失效，也会影响已装的快捷方式。

### 2.2 触摸屏无法自然滚动设置页

**现象**：用触摸屏在设置页上下滑动，页面不动。
鼠标滚轮正常。

**根因**：`NavigationView` 内部的 `ScrollViewer` 先吃掉了触摸事件。
各设置页自己都设了 `PanningMode`，但被外层截住了，设了也不生效。

**修复**：给外层 `NavigationView` 补 `ScrollViewer.PanningMode="VerticalFirst"`
和 `PanningDeceleration`。

**排查顺序的教训**：查「谁吃掉了输入」要从外往里查，不是从里往外。

### 2.3 PPT 放映退出后残留透明条

**现象**：退出 PPT 放映，屏幕上留一条半透明遮罩，
挡着下面的窗口，点也点不掉。

**根因**：`GridTransparencyFakeBackground` 的 opacity 和命中测试状态没复位。
只有部分退出路径会复位，其余路径残留。

**修复**：加 `ResetPptTransparencyOverlay(reason)`，幂等，挂在所有退出路径上。

### 2.4 PPT 翻页栏在 COM 事件缺失时不出现

**根因**：只依赖 PowerPoint 的 COM 事件刷新页数。
事件丢失时，翻页栏一直显示旧数据或者根本不出现。

**修复**：轮询路径也补刷 `SlidesCount`，不再单靠事件。

### 2.5 PPT 连接失败时完全没有提示

**根因**：连接失败的异常被静默吞掉，日志里一个字都没有。

**修复**：把失败原因写进日志（区分 COM 权限、PowerPoint 未运行等情形）。

## 三、可用性改进

### 3.1 设置页结构重整

上游的设置页是把所有开关平铺出来，本分支按使用场景重新归组：

- 「画板」页拆开，项按性质迁到该在的页
- 调试项收进折叠组，不占视线
- 十几条开发文档式的说明改写成使用者能看懂的话
- 去掉只有一个子项的空分组

### 3.2 界面中文化

设置页里原本硬编码的英文字符串收进 resx，支持中英切换。

### 3.3 动画改成弹簧引擎

**上游做法**：`Storyboard` 配固定缓动曲线。
连续操作时前一个动画被打断，会跳帧。

**本分支**：换成弹簧模型，能被打断并平滑接上。

**刻意没换的地方**：`InkFadeManager`。
它的 `Storyboard` 由时钟驱动，窗口最小化后仍然推进；
弹簧走 `CompositionTarget.Rendering`，窗口最小化就停了。
换掉会导致笔迹淡出不完整。**这是有意的例外，不是漏改。**

### 3.4 日志里的开发期探针

**上游**：每 5 秒往日志写一条内部指标。
实测最大一份日志 109 行里有 52 行是它，占 48%。
真出问题时，关键信息会被这些记录淹掉。

**本分支**：删除该探针，日志回到只记事件。

### 3.5 OOBE 首启引导里的技术名词

**上游**：首次启动引导的窗口背景样式下拉列了 7 项，
其中 6 项是 Windows 11 的内部名称（云母 / 亚克力 / Tabbed / Transient / 亚克力10 / 亚克力11），
老师完全不知道该选哪个。

**本分支**：只在下拉里显示 3 个常用项，其余 4 项保留但不再展示。

**为什么不是直接删掉这 4 项**：
`SelectComboBoxItemByTag` 找不到 Tag 会静默选第一项，
`WindowBackdropHelper` 的 `Enum.TryParse` 失败会降级成 `None`。
直接删会让老用户的背景设置被悄悄关掉，且不给任何提示。
所以是「保留 Tag，只在下拉里隐藏」。

### 3.6 工具栏里的说明书入口

**上游**：工具栏留着「说明书」菜单项，但对应的窗口早已不存在，
点开没有反应。

**本分支**：连同注册表项、图标映射、事件绑定一并删除，不留死代码。

## 四、刻意没做的

| 项 | 为什么 |
|---|---|
| **不做程序集裁剪（PublishTrimmed）** | WPF 靠反射绑定 XAML，裁剪后是运行时崩，不是编译期报错。课堂上才会发现 |
| **不改 `AssemblyName`** | 会让「检测原版是否在运行」的判断失效 |
| **不换 `InkFadeManager`** | 见 3.3，弹簧在窗口最小化时不推进 |
