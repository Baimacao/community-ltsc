# 为什么 LTSC 1.7.19.7 在最坏情况下比原版更不容易在课堂上崩

**一句话**：不是因为它代码少，是因为**原版把「崩溃」变成了「静默消失」，而 LTSC 让它变成「看得见、有出路」。**

---

## 最坏情况是什么

课堂上最坏的不是「弹个报错」，是**老师正在写板书，程序没了，屏幕上什么提示都没有**。
一屋子学生看着，老师只能当场重开。

原版在三条路径上会走到这个结局：

### 路径一：崩溃时不弹窗、不重启，直接消失

`MW_SettingsToLoad.cs` 原来是：
```csharp
if (Settings.Startup.CrashAction == 0) App.CrashAction = SilentRestart;
else                                   App.CrashAction = NoAction;
```
而枚举是 `SilentRestart=0 / NoAction=1 / ShowCrashWindow=2`，**默认值是 2**。
这个二值归约把默认行为打成了 `NoAction`——崩溃时连 `CrashWindow` 都不弹。

**LTSC**：改成三档一一映射。默认配置下崩溃会弹窗，老师能看到发生了什么。

### 路径二：设了「静默重启」，但重启机制根本没启动

`App` 构造函数里判断 `CrashAction == SilentRestart` 来决定是否拉起看门狗进程，
而那一刻 `CrashAction` 还是字段默认值（`ShowCrashWindow`），`Settings.json` 要到
`App_Startup` 才读。**用户改成「静默重启」之后，必须整个重启应用才生效，UI 上没有一个字提示。**

结果是最讽刺的一种：老师特意配了「崩了就自动重启」，真崩了却什么也没发生。

**LTSC**：把读配置提前到看门狗判断之前。改完立即生效。

### 路径三：每次写日志都在全量 GC + 重扫文件锁

`ProcessProtectionManager.WithWriteAccess` 每次写入前执行：
```csharp
GC.Collect(GC.MaxGeneration, GCCollectionMode.Forced, true);
GC.WaitForPendingFinalizers();
```
写完再把整棵目录树重新扫描加锁。而**日志和配置全走这条路**——日志调用点 1705 处、
配置保存 404 处。其中 `MW_TouchEvents.cs:948` 在**每次笔落且处于线擦模式时**写一条日志。

这是路径一/二的上游：UI 线程被 GC 拖长，心跳判据（`sinceHeartbeat > 10s`）就越容易命中，
而心跳一旦命中就走「重启」，重启又依赖路径二那条根本没启动的链路。

**LTSC**：进程保护整块移除（所有者裁决「没用」）。写入路径上不再有强制 GC。

---

## 为什么这不是「删了功能所以更稳」

这个说法通常意味着「牺牲能力换取稳定」，那是坏事。这里不是：

| 保留的东西 | 状态 |
|---|---|
| 崩溃监听（4 个来源） | 保留 |
| CrashWindow 弹窗 | **修好了**（原来被吃掉） |
| 心跳守护 + 看门狗 + 5 次熔断 | 保留，且**时序修对了** |
| PPT 联动 COM / ROT | 保留（只删了 Agent 架构） |
| 墨迹全家桶（平滑/压感/识别/保存/撤销） | **一行没动** |
| 插件公共契约 | **一行没删** |
| 三模式 / 浮动栏 / 截图 | 保留 |

删掉的是：自动更新、通知公告、进程保护、旧版图标、Agent 架构、智能模式。
**没有一项在「老师正在写字」的那一刻起作用**；而进程保护和自动更新恰恰会在那一刻抢资源。

---

## 三条「看得见」的保证

1. **崩溃可见**：默认配置下崩了会弹 `CrashWindow`，带可复制的异常信息。
2. **版本可见**：更新功能删了，但 `AboutPage` 仍从程序集直接读版本号显示（`AboutPage.xaml.cs:103-112`），
   这条不依赖更新模块。用户永远知道自己跑的是哪一版。
3. **可回归**：`REMOVED.md` 里每一条都写了 `git revert` 路径，且所有删除都在独立分支上，
   上游 tag `1.7.19.7` 原样未动。

---

## 我**没有**证明的事

- 没有在真实课堂设备上跑过。本机没有触屏、没有 PowerPoint、没有希沃一体机。
- D-03 的人工注入故障步骤写在 `verification.md` 里，**我没有执行**。
- 性能数字（CPU、工作集、帧间隔）**一个都没有测**。进程保护移除带来的收益是结构性的
  （代码路径上不存在强制 GC），不是实测出来的。

任何声称「更快了」而没有数字的说法，都是编的。

---

## 一句话总结

原版的问题不是功能多，是**保护机制自己坏了却没人知道**：
弹窗被归约吃掉、看门狗按默认值判断、写入路径上强制 GC。
LTSC 做的是让这些机制按它们本来的设计工作，然后把在课堂上只会抢资源的功能拿掉。
